# Synthetic Data Package

All records, people, organizations, clinical facts, research records, and workflow events in this
directory are fictional. **Synthetic only. No PHI. Not clinical decision support.** The package was
created for this repository and was not copied from patient records, customer environments,
institutional documents, protected protocols, licensed guidelines, production telemetry, or public
trial records.

Names are generic fictional placeholder names; any resemblance to a real person or organization is
coincidental. `AMC IQ`, its clinics, `SITE-*` locations, and all staff roles are fictional.

## Layout

| Dir | Feeds | Contents |
|---|---|---|
| `registry/` | **everything** | `registry.yaml` (source of truth) + `loader.py` |
| `foundry_docs/` | **Foundry IQ** (Blob KS) | synthetic protocols + amendment, policies, SOPs, escalation rules, pathway summary, oncology note, pathology, genomics, and tumor-board summary |
| `fabric/` | **Fabric IQ** (Lakehouse) | 16 entity CSVs generated by `generate.py`: sites, people, patient_registry, biomarkers, labs, treatment_history, comorbidities, adverse_events, recist_assessments, consent, trials, trial_criteria, amendments, trial_enrollment, coordinator_workload, scheduling_slots (+ `README.md`, `data_dictionary.md`) |
| `work/` | **Work IQ** (M365) | tumor board summary, coordinator handoff, referral_queue, open_tasks, pi_availability, teams_messages |
| `web/` | **Web IQ** (synthetic snapshots) | ClinicalTrials.gov-style record (JSON + HTML), drug-label-style summary, guideline-style summary, evidence abstract, manifest |

## Authorship and generation

- `registry/registry.yaml` is the hand-maintained source of truth for identifiers and pinned scenario
  facts.
- `ontology/ontology.yaml` is the hand-maintained entity and relationship contract.
- `fabric/*.csv` is code-generated by `fabric/generate.py`.
- `foundry_docs/`, `work/`, and `web/` contain original synthetic prose and fixtures drafted for
  this project, including AI-assisted drafting followed by repository review. They are not
  transcriptions, excerpts, or close paraphrases of protected source material.
- The web fixtures simulate source types for retrieval testing; except for the currently
  non-resolving ClinicalTrials.gov trial link, their provenance URLs use the reserved `.invalid`
  domain and do not claim an external publication.

The Fabric generator is deterministic and idempotent. Its default master seed is
`amc-iq-fabric-2026`, combined with each entity key, so repeated runs produce byte-identical tables
with canonical LF line endings regardless of operating system or Python hash randomization.

Regenerate the structured tables with:

```bash
python data/fabric/generate.py
```

For a local reset, rerun the generator; it overwrites all 16 generated CSVs. For a deployed sandbox,
rerun the relevant Fabric, Foundry, Work IQ, and Web IQ provisioning/seed commands documented under
`agent/provisioning/live/` after resetting the target resources.

## Relationships and provider use

The entity graph is defined in `ontology/ontology.yaml`: patients link to clinicians, biomarkers,
labs, treatments, comorbidities, adverse events, RECIST assessments, consent, enrollment, and
scheduling; trials link to criteria and amendments. Each criterion names the patient fact entity and
attribute it evaluates.

- Foundry IQ consumes `foundry_docs/`.
- Fabric IQ consumes the 16 generated tables under `fabric/`.
- Work IQ consumes `work/`.
- Web IQ consumes `web/`.
- The local mock evaluator consumes the same Fabric CSV facts and trial criteria.

## Validate consistency

```bash
python tools/validate_consistency.py
```

Confirms every `PT-####` / `NCT########` token in the data package is defined in the registry, and
that the hero patient/trial appear in the expected layers. A complete validation also regenerates
the Fabric tables and confirms no tracked output changes.
